# Editorial gallery design

Owner feedback (2026-11-16) identified typography, layout and sizing as
areas for further refinement. The historical MIC-29 captures show the earlier
implementation.

## Homepage direction

Home opens with a first-person introduction and brings selected work into the
first viewport. A charcoal surface, quiet row dividers and compact
project descriptions give the real project media room to lead. Journal and
newsletter sections use the paper palette. Each project row links
to its full story for details and attribution. The Chromatique case study
links directly to the interactive palette comparison in Lab.

Home, Work and Lab share the charcoal masthead and site gutters. The
first Home project column follows the header’s four-column grid on desktop.
On Home, the 53% desktop gallery frame exposes most of the next image.
Phones use 76% frames and tighter spacing to bring project media into the
opening viewport.

## Lab and navigation motion

Lab presents the interactive colour comparison from Chromatique.
Play keeps its project and community directory and its existing interactions.
Work, Lab and Play share the site gutters and project typography. Lab and
Play use project directories with covers.
Their cover images and the Chromatique comparison use responsive static WebP
variants generated by `bun run build:previews` for development and production.
Lab prioritizes its first cover and defers the comparison until it nears the
viewport. Play loads the comparison eagerly.

On client-side navigation, the previous page moves up and fades over 180 ms
while the new content rises and settles over 380 ms. The header and footer
stay clear of that movement. The navigation underline draws in over 220 ms.
A short entrance covers browser history restores and browsers without snapshot
support. Initial loads, hash navigation and query changes use the browser’s
usual behavior. Reduced motion skips the effects.

## Complete project index

Work uses native CSS columns for the collection, from one on phones to two
on tablets and three on desktops. Cards stay intact, and the inventory order
runs down each column, matching keyboard and screen reader order. The
reference’s Explore page pairs differently proportioned visuals with compact
captions. Work opens the collection with Chromatique’s source photograph
and keeps every project within the page gutters. The selected project galleries
remain above the index, and Home links directly to the collection.

The cover proportions reserve space before the lazy preview loads. Available
project photos, captures, diagrams and official share artwork use the
existing media paths and static derivatives. Entries without source media use
shallower editorial wordmarks in the existing experiment palette. The same composition
shows through if a preview fails. CSS columns cover the layout and reading
order without a library or client measurement.

## Typography

MIC-119 uses Instrument Sans for the editorial interface. Fontsource supplies
OFL-1.1 variable WOFF2 files for Latin and Latin Extended. The site uses 400 for
display and prose, with 500–700 available for emphasis and controls. Next.js
preloads the Latin face and provides a metric-adjusted Arial fallback. Both
subsets use optional display so a slow response keeps the first layout stable.
Code retains the system monospaced stack.

The [reference](https://www.daniilch.design/) rendered its opening copy at 32px,
project titles and descriptions at 18px, and navigation at 13px at 390, 834 and
1440px. The portfolio adapts its quiet regular weight and compact supporting
text while retaining the oversized headings from the approved compositions.
Shared styles set display headings at 48–144px, reader titles at 36–72px, leads
at 18–26px, prose at 18–20px, and navigation and captions at 16px at the default
root size. Intro leads use a 32ch measure and the reader uses 68ch for prose.

## Layout and project media

MIC-120 uses fluid page gutters and intro spacing, a compact shared header, and
approximately 28–44px of padding at each edge of a project row. Project copy
stacks above media on phones and occupies one quarter of the available row at
tablet sizes and one fifth on desktop. This follows the [reference's project
rows](https://www.daniilch.design/) in giving the media most of the available
width and aligning the controls at the trailing edge.

The reference shows two tall frames across on desktop. Our landscape media
uses one wider frame with a visible slice of the next item. Slides with
neighbours take 88%, 84% and 76% of the carousel at phone, tablet and desktop
widths respectively. Captions, credits and full-size links sit below each
frame. Native scrolling and the accessible 44px controls share the same
endpoints. Owner visual acceptance is tracked in MIC-123.

The five mockups attached to MIC-8 document the original visual direction.
Their oversized regular-weight typography still informs the inner pages.
Narrow project descriptions and generous media carry forward.

Component design follows atomic composition: shared primitives → small component
groups → reusable sections → templates/pages. Reuse the existing UI and tokens;
extract shared responsibilities as they emerge. Prefer established, maintained
libraries for standard interaction patterns, starting with Radix/shadcn. Check
accessibility, server rendering, no-script behaviour and bundle cost before
choosing a library or custom code. Keep component layout/states in Tailwind and
reserve global CSS for theme tokens and global defaults. This is a composition
principle, not a requirement to rename every folder or wrap every HTML element.
